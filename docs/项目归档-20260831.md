# 抖音聊天多开管理器 — 项目归档

> 归档时间: 2026-08-31
> 会话时长: ~5小时
> 项目路径: `C:\Users\Administrator\Documents\agi\douyin_auto\`

---

## 一、项目目标

在一台 Windows 电脑上同时运行多个抖音聊天实例，每个实例独立登录不同账号，互不干扰。

---

## 二、核心技术方案

### 2.1 多开原理

抖音聊天是 Electron 应用（v1.1.33），通过修改 `app.asar` 实现多开：

- **绕过单实例锁**: 将 `if(!e.app.requestSingleInstanceLock())return e.app.quit(-1),!0` 替换为 `if(!1)return e.app.quit(-1),!0`
- **独立数据目录**: 将 `setPath("userData",..."抖音聊天")` 改为 `setPath("userData",..."抖音聊天N")`

**不做的事情**（会触发反篡改导致登录崩溃）:
- ❌ 不改 `package.json` 的 `name`/`productName`
- ❌ 不注入 JS 覆盖 `os.cpus()`/`os.networkInterfaces()`/`app.getGuid()`

### 2.2 DPI 问题

系统 DPI 125%（逻辑 1536x864，物理 1920x1080）。
- 所有自动化操作必须先调用 `SetProcessDPIAware()` 统一为物理坐标
- 不调用会导致点击偏移，甚至让窗口最小化

### 2.3 窗口置前

使用 `AttachThreadInput` + `SetForegroundWindow` + ALT键技巧绕过 Windows 前台锁定。

## 三、已实现功能

### 3.1 管理器 (manager.ps1)
- 状态总览：运行时间、CPU/内存/温度、出口IP（绕过梯子代理显示真实IP）
- 账号状态检测：
  - 运行中实例：看窗口标题判断在线/需登录
  - 停止实例：读 Cookies 数据库的 sessionid 有效期判断
- 操作：启动/停止/新建/删除实例、编辑备注
- 安全退出：用 `CloseMainWindow()` 替代 `Stop-Process -Force`，触发 `before-quit` 钩子避免掉线

### 3.2 补丁脚本 (patch_fingerprint.js)
- 从原版 app.asar 解包 → 修改 userData 路径 + 绕过单实例锁 → 重新打包
- 每次补丁都从原版 asar 开始，不累积修改

### 3.3 登录状态检测 (read_cookie.js)
- 用 Node.js better-sqlite3 的 `immutable` 模式读取被 Chromium 锁住的 Cookies 数据库
- 检查 sessionid 的 expires_utc 判断凭证有效期

### 3.4 开机自启
- Windows 计划任务 `DouyinMultiInstance`，登录时自动启动所有小号
- 间隔 15 秒逐个启动避免冲突

## 五、踩过的坑

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 点击偏移/窗口最小化 | DPI 缩放未处理 | 调用 SetProcessDPIAware() |
| 改 app name 后登录崩溃 | 服务端校验 app 身份 | 不改 name，只改 userData |
| 注入 os.cpus/os.networkInterfaces 后崩溃 | 触发反篡改检测 | 不注入，只做数据目录隔离 |
| 重启后所有账号掉线 | 进程被强杀，before-quit 未触发 | 用 CloseMainWindow() 安全退出 |
| Cookie 文件读取失败 | Chromium 锁住 SQLite | 用 better-sqlite3 的 immutable 模式 |
| 检测"凭证有效"但实际已掉线 | uid 文件夹掉线后仍存在 | 不用 uid 判断，用 Cookie sessionid 有效期 |
| node -e 内联 JS 转义问题 | PowerShell 引号冲突 | 改用独立 .js 文件 |

## 七、待优化

1. **重启掉线问题**: 目前只能通过管理器的"全部停止"安全退出，无法防止强制重启（断电/系统更新）。可考虑添加"安全重启"功能。
2. **账号过期提醒**: 小号4 的 sessionid 即将过期，需要及时续签或重新登录。
3. **批量扫码**: 当前每个实例都需要手动扫码登录，无法自动化。
4. **设备指纹**: 只做了数据目录隔离，所有实例共享同一设备指纹（MAC/CPU/磁盘序列号），存在关联风险。
